# Sprint S22 - Files semantics (cardinality + eventual consistency + discovery)

## Objetivo (1 frase)
- Hacer explícita la semántica de ficheros por capability (cardinalidad y efecto de ingesta), exponerla en discovery (nativo y A2A) y propagar metadatos de ingesta sin prometer coherencia que el agente no garantiza.

## In (scope)
- S22-T01 a S22-T06.

## Out / No-goals del sprint
- No se implementa un orquestador genérico de workflows multi-request.
- No se añade espera/polling para “garantizar indexación” ni se auto-promueve a `deferred` por presencia de ficheros.
- No se introduce una cola por instancia.
- No se cambia el contrato de tareas (S21) salvo la documentación de interacción entre tareas y ficheros.

## Dependencias
- Depende de: S05 (decoders), S06 (templates/mapping), S13–S14 (gateway interact).
- Relación con S21: complementario (S21 define `response_mode`; S22 define semántica de ficheros y su visibilidad).

  - Comando: make ci
  - Pass: ejecuta `gleam format --check ...`, `gleam test`, `gleam test --coverage` sin errores
