# S20-T04 - Landlock strict policy (configurable) + FS deny/allow proof

## Sprint
- Sprint: S20
- Capa: Wrapper + Config + Integration tests
- Riesgo: Alto
- Gate: No

## Objetivo
- Provide a configurable (TOML) Landlock policy that is compiled by SAD into an effective per-instance policy, and prove with deterministic integration tests that:
  - The runner can read/write inside its workspace.
  - The runner cannot read/write outside its workspace.

## Policy contract (normative)

### TOML schema
- `[security]`
  - `landlock_mode = "off"|"best_effort"|"enforced"`
- `[security.landlock]` (required when `landlock_mode = "enforced"`)
  - `allow_read = ["/abs/path", ...]`
  - `allow_exec = ["/abs/path", ...]`
  - `allow_write = ["/abs/path", ...]`

### Effective policy (per instance)
SAD MUST compile an effective policy per instance and pass it to the wrapper.
The wrapper MUST NOT infer or extend the policy.

- Env var: `SAD_LANDLOCK_POLICY_JSON`
- Format (exact):

```json
{
  "allow_read":  ["/etc", "/proc/self", "/abs/workspaces/workspace-<id>"],
  "allow_exec":  ["/usr", "/bin", "/lib", "/lib64"],
  "allow_write": ["/tmp", "/var/tmp", "/abs/workspaces/workspace-<id>"]
}
```

Rules:
- All entries MUST be absolute paths.
- The effective policy MUST include the instance workspace path in both `allow_read` and `allow_write`.
- `"/"` MUST be rejected in any list.
- Dot-segments MUST be rejected (`/./`, `/../`, trailing `/.` or `/..`).

### Stable errors (early fail)
When `security.landlock_mode = "enforced"`, SAD MUST fail early at config load time.
The error message MUST include a stable marker to allow tests to assert it.

Stable markers (exact strings):
- `LANDLOCK_POLICY_MISSING`
- `LANDLOCK_POLICY_PATH_NOT_ABSOLUTE`
- `LANDLOCK_POLICY_PATH_IS_ROOT`
- `LANDLOCK_POLICY_PATH_HAS_DOT_SEGMENT`
- `LANDLOCK_POLICY_PATH_IS_SYMLINK`
- `LANDLOCK_WORKSPACES_DIR_NOT_ABSOLUTE`

Notes:
- Tests assert on these markers only (not on full human text).
- Symlink detection MUST be done during config load (fail early).

## Limites y defaults (obligatorio)
- security.landlock_mode: best_effort
- Policy lists: empty for non-enforced modes (allowed), required for enforced.
- workspaces.directory: must be absolute in enforced.

## Acceptance Criteria (obligatorio)
- Casos correctos:
  - In enforced mode, with a valid policy and an instance workspace injected, the runner can read/write inside workspace.
  - In enforced mode, the runner cannot read or write outside workspace (deterministically tested using an existing sibling directory outside the workspace).
  - The policy is configured via TOML with absolute paths only.
  - The wrapper does not add implicit allowlist entries: removing workspace from the JSON must cause workspace writes to fail.
- Casos incorrectos:
  - Config with relative allowlist paths is accepted.
  - Config with allowlist path "/" is accepted.
  - Config with "/../" or "/./" segments is accepted.
  - Config with symlink allowlist paths is accepted.
  - In enforced mode, invalid policy is detected late (runtime) instead of failing early at config load.

## Semantica de errores (obligatorio)
- ErrorKind esperado:
  - Config load errors: operational error (sad config error), fail before server start.
  - Runtime enforced wrapper errors: infra_error with stable marker `LANDLOCK_UNAVAILABLE`.
- ProblemDetails esperado:
  - N/A

## Notas de diseño / auditoria
- Deterministic deny/allow proof must not rely on system directories like `/root`.
  The tests must create an existing, writable directory outside the workspace (e.g. `<workspaces.directory>/denied`) and attempt to access it via `../denied/...`.
- Validation must be strict:
  - absolute-only
  - reject root
  - reject dot and dotdot segments
  - reject symlink paths (MUST check the configured path itself is not a symlink; `realpath(path) != path` is sufficient for the test contract).

## No-goals (obligatorio)
- Per-profile allowlists or capability-specific policies.
- Network sandbox.
