# S22-T05 - Discovery: exponer semántica en views nativas y AgentCard A2A

## Sprint
- Sprint: S22
- Capa: Gateway + A2A facade
- Riesgo: Medio
- Gate: No

## SSOT (obligatorio)
- `docs/arquitectura/gateway.md` - endpoints y views
- `docs/arquitectura/integracion.md` - discovery por capability
- `docs/arquitectura/protocolos.md` - wire format A2A y Agent Card
- A2A: AgentCard (servidor) + consumo por cliente

## Inputs (obligatorio)
- Supuestos:
  - Los clientes A2A descubren capacidades vía AgentCard (`/.well-known/agent-card.json`).
  - Los clientes nativos descubren capabilities vía `GET /agents/:instance_id`.

## Outputs (obligatorio)
- Catálogo:
  - Añadir/actualizar el catálogo de extensiones A2A en `docs/arquitectura/protocolos.md` cuando se introduzca una extensión nueva.

- Nativo:
  - Incluir en la vista de capabilities (GET /agents/:id) los campos:
    - `files.accepts`, `files.max_files`, `files.ingest_effect`.

- A2A server (AgentCard):
  - Extender el AgentCard generado desde Profile/Instance para incluir información consumible por clientes sin leer el perfil.
  - `skills[].inputModes` se deriva del `input_schema` de la capability:
    - `std:chat` -> `["text"]`
    - `std:files` -> `["file"]`
    - `std:mixed` -> `["text", "file"]`
  - `skills[].outputModes` (best-effort):
    - incluir siempre `"text"`
    - incluir `"data"` si SAAR puede devolver artifacts/metadata estructurada para esa capability

  - Semántica de ficheros como extensión forward-compatible (no requiere cambios en el protocolo A2A):
    - Añadir a nivel root un listado `extensions` con el URI (placeholder):
      - `urn:saar:extensions:files-semantics:v1`
    - Añadir a nivel de skill un objeto `extensions` (clave = URI) con:
      - `maxFiles: Int`
      - `ingestEffect: "immediate" | "eventual"`
    - Ejemplo (fragmento):

      ```json
      {
        "skills": [
          {
            "id": "files",
            "inputModes": ["file"],
            "outputModes": ["text"],
            "extensions": {
              "urn:saar:extensions:files-semantics:v1": {
                "maxFiles": 1,
                "ingestEffect": "eventual"
              }
            }
          }
        ]
      }
      ```

- A2A client guidance:
  - Si `ingestEffect=eventual`, el cliente no debe asumir que un upload afecta inmediatamente a queries siguientes.
  - Si el cliente quiere UX robusta, debe tratar la ingestión como side-effect eventual (p.ej. mostrar aviso, o reintentar/esperar de forma explícita).

## Acceptance Criteria (obligatorio)
- Casos correctos:
  - Un cliente puede descubrir `max_files` sin leer el JSON del perfil.
