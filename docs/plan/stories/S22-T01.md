# S22-T01 - Types + decoders: files semantics por capability

## Sprint
- Sprint: S22
- Capa: Profiles (types/decoders)
- Riesgo: Medio
- Gate: No

## SSOT (obligatorio)
- `docs/arquitectura/integracion.md` - modelo mental de capabilities
- `docs/arquitectura/protocolos.md` - tipos y wire
- `docs/arquitectura/examples/profiles/lightrag/lightrag_vnext.json` - ejemplo con `files` eventual
- `src/sad/types/profile.gleam` - tipos de Profile/Capability
- `src/sad/decoders.gleam` - decoders de perfil

## Inputs (obligatorio)
- Supuestos:
  - `std:mixed` existe como schema para agentes que aceptan texto+ficheros en la misma interacción.
  - Para agentes que NO aceptan mixed, se modelan capacidades separadas (por ejemplo `chat` y `files`).

## Outputs (obligatorio)
- Diseño (perfil): añadir un bloque opcional por capability llamado `files` (nombre provisional) con:
  - `accepts: Bool`
  - `max_files: Int` (0 para “no acepta”, 1, N)
  - `ingest_effect: "immediate" | "eventual"` (solo si `accepts=true`)
- Validaciones (en decoder):
  - `max_files >= 0`
  - si `accepts=false` entonces `max_files == 0`
  - si `accepts=true` entonces `max_files >= 1`
  - si `ingest_effect` está presente, `accepts` debe ser true
- Código:
  - Actualizar `src/sad/types/profile.gleam` para incluir el tipo.
  - Actualizar `src/sad/decoders.gleam` para decodificar y validar.

## Acceptance Criteria (obligatorio)
- Casos correctos:
  - Perfiles existentes siguen cargando sin cambios.
  - `lightrag_vnext.json` decodifica con `files.max_files=1` e `ingest_effect=eventual`.
- Casos incorrectos:
  - `accepts=false` con `max_files=1` se rechaza.

## Semántica de errores (obligatorio)
- ErrorKind esperado:
  - `bad_request` en carga/validación de perfil inválido.
