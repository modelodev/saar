## Inputs (obligatorio)
- Supuestos:
  - Sin replay: al reconectar, el cliente recibe un snapshot del estado actual y sigue desde ahí.
  - El cliente puede preferir suscripción (SSE) en vez de sondeo.

## Outputs (obligatorio)
- API nativa:
  - `GET /tasks/:task_id/subscribe` (SSE)
    - Primer evento: snapshot del estado actual de la tarea
    - Eventos siguientes: cambios de estado (y el resultado final cuando complete)
    - El stream se cierra al alcanzar un estado terminal
- Idempotencia:
  - Si `POST /agents/:instance_id/interact` (deferred) llega con el mismo `context.trace_id`, SAD devuelve la misma tarea (no crea duplicados).
- Tests (inventario exacto):
  - `test/integration/tasks_subscribe_test.gleam`:
    - `subscribe_first_event_is_task_snapshot`
    - `subscribe_closes_on_terminal_state`
    - `subscribe_after_completion_returns_terminal_snapshot_immediately`
  - `test/integration/deferred_idempotency_test.gleam`:
    - `post_deferred_same_trace_id_returns_same_task`

## Límites y defaults (obligatorio)
- Reusar `limits.sse_keep_alive_interval_ms` para keep-alive.

## Acceptance Criteria (obligatorio)
- Casos correctos:
  - Un cliente puede “engancharse” a una tarea existente y ver su finalización.
  - Dos envíos con el mismo `trace_id` no generan dos tareas.
- Casos incorrectos:
  - La suscripción empieza sin snapshot (crea huecos de estado).

## Semántica de errores (obligatorio)
- 404 si la tarea no existe.

## Evidence reproducible (obligatorio)
- `gleam test` con exit 0.

## No-goals (obligatorio)
- No se envían fragmentos de texto incremental en modo diferido (solo estado + resultado final).
