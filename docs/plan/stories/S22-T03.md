# S22-T03 - HTTP multipart: mapping estable para 0/1/N y metadata de ingesta

## Sprint
- Sprint: S22
- Capa: Bridge/HTTP
- Riesgo: Alto
- Gate: No

## SSOT (obligatorio)
- `docs/arquitectura/examples/profiles/lightrag/lightrag_vnext.json` - files: upload + track_id
- `src/saar/bridge/http_client.gleam` - multipart y fetch
- `src/saar/response_mapping.gleam` - extracción de texto

## Inputs (obligatorio)
- Supuestos:
  - Un agente HTTP puede tener una capability `files` que acepte solo 1 fichero (`max_files=1`).
  - La respuesta del upload puede incluir un identificador (`track_id`) pero su significado es del agente.

## Outputs (obligatorio)
- Soporte de `response.capture` (nombre provisional) para capabilities HTTP:
  - Permite extraer campos de la respuesta upstream por JSON Pointer y adjuntarlos a `metadata`.
  - Ejemplo: `track_id`.
- Reglas:
  - Captura es puramente informativa; no modifica el modo de respuesta ni garantiza indexación.

## Acceptance Criteria (obligatorio)
- Casos correctos:
  - Upload con 1 fichero devuelve 200 y `metadata` incluye `track_id` (si existe en response).
- Casos incorrectos:
  - Si el pointer de captura no existe, no debe fallar; solo no se incluye el campo.

## Tests (inventario exacto)
- `test/integration/files_ingest_metadata_test.gleam`:
  - `files_upload_includes_track_id_when_present`
  - `files_upload_missing_track_id_does_not_fail`

## Evidence reproducible (obligatorio)
- `gleam test` con exit 0

## No-goals (obligatorio)
- No se espera a que el agente termine de indexar.
