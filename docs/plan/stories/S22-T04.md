# S22-T04 - Gateway interact: propagar ingest metadata a respuestas (sin promesas)

## Sprint
- Sprint: S22
- Capa: Gateway
- Riesgo: Medio
- Gate: No

## SSOT (obligatorio)
- `docs/arquitectura/gateway.md` - shape de respuestas
- `docs/arquitectura/integracion.md` - experiencia de cliente
- `RUNNERS_AND_AGENTS.md` - semántica de capabilities

## Inputs (obligatorio)
- Supuestos:
  - Si un agente (o capability) tiene ingesta eventual, SAD no debe transformar eso en tareas ni en esperas; debe exponerlo.

## Outputs (obligatorio)
- API nativa:
  - Cuando una interacción implica ingestión de ficheros (por ejemplo llamando a la capability `files`):
  - Incluir en `ResponseData.metadata` un bloque estable, por ejemplo:
    - `ingest_effect: "eventual" | "immediate"`
    - `track_id: String?`
    - `max_files: Int`
- La respuesta del `chat` no debe prometer que un documento recién subido será usado.

- A2A:
  - Cuando un cliente invoca la skill `files`, el resultado debe incluir los mismos metadatos de ingesta de forma consumible por un cliente A2A.
  - Propuesta v0: incluir un `DataPart` en la respuesta (sync o stream) con un objeto estable `ingest`:
    - `{"data":{"data":{"ingest":{"effect":"eventual"|"immediate","trackId":String?,"maxFiles":Int}}}}`
  - Este metadata es informativo: no implica garantía de indexación.

## Acceptance Criteria (obligatorio)
- Casos correctos:
  - El cliente puede mostrar un aviso al usuario usando solo la metadata.
- Casos incorrectos:
  - SAD no debe declarar éxito de indexación si solo tiene un `track_id`.
