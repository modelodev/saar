## Inputs (obligatorio)
- Supuestos:
  - El error por cardinalidad inválida es input inválido, no “busy”: debe ser `400`.

## Outputs (obligatorio)
- Validación runtime (nativo y A2A):
  - La validación de cardinalidad se aplica tanto a la API nativa (`/agents/:id/interact`) como a la fachada A2A (`message:send` / `message:stream`).

- Validación runtime:
  - Si la capability declara `files.max_files=0` y el payload contiene ficheros -> `400`.
  - Si `files.max_files=1` y el payload trae 2+ ficheros -> `400`.
  - Si `files.max_files=N` y el payload trae `>N` -> `400`.
- ProblemDetails:
  - `400` con un tipo estable (por ejemplo `invalid_input`) y detalle que incluya:
    - `capability`
    - `max_files`
    - `received_files`

## Acceptance Criteria (obligatorio)
- Casos correctos:
  - Payload con 1 fichero cuando `max_files=1` -> no falla por cardinalidad.
- Casos incorrectos:
  - Payload con 2 ficheros cuando `max_files=1` -> `400`.
