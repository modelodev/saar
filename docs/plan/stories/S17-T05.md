## Outputs (obligatorio)
- Codigo:
  - src/sad.gleam:
    - Implementar `main()` real: leer argv, parsear con `sad/cli.parse`, ejecutar.
    - `--help` imprime en stdout y retorna exit 0.
    - `--version` lee `version` desde `./gleam.toml` y lo imprime en stdout (fallback: "unknown"), exit 0.
    - Errores de uso (parse error) imprimen en stderr y retornan exit 1.
    - Comandos parseables pero no implementados retornan exit 2 (operational) con mensaje en stderr.
    - `sad serve` (foreground) arranca el servidor HTTP (bloquea) y, al arrancar, imprime la configuración efectiva usada (host/port/config_path).
    - `sad serve -b/--background` daemoniza el *mismo binario SAD* (no un comando arbitrario).
    - `sad serve -k/--kill` y `sad serve --status` ejecutan usando `sad/daemon_paths` + `sad/daemon_control`.
  - Para testabilidad (sin spawn del servidor en unit tests), extraer una función pura para planificar la ejecución:
    - `sad.run(argv: List(String), get_env: fn(String) -> Result(String, Nil), read_file: fn(String) -> Result(String, Nil)) -> RunPlan`
    - Donde `RunPlan` es un ADT que describe: `exit_code`, `stdout_lines`, `stderr_lines` y, si aplica, el `ServePlan` (port/config_path/pid/log/mode).
    - `main()` debe ser un thin wrapper sobre `run()` + efectos IO.

## Acceptance Criteria (obligatorio)
- Casos correctos:
  - `sad --help` retorna exit 0.
  - `sad --version` retorna exit 0 e imprime una versión (desde `gleam.toml`).
  - `sad serve` (foreground):
    - Si no hay flags, usa defaults.
    - Si hay flags, flags sobrescriben defaults.
    - Imprime la configuración efectiva al arrancar (al menos: host, port y config_path).
  - `sad serve --status`:
    - Si hay pidfile vivo: imprime `SAD running on port <port> (PID <pid>)` (stdout), exit 0.
    - Si no está corriendo: imprime `SAD not running` (stdout), exit 1.
  - `sad serve -k`:
    - Si mata un proceso: exit 0 y borra pidfile.
    - Si no hay servidor: exit 1.

- Casos incorrectos:
  - Uso inválido (parse error) retorna 1 (nunca 0).
  - Comando parseable pero no implementado retorna 2 (operational) y no hace `panic`.
