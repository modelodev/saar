# S23-T01 - Config hot-reload with validation (TDD)

## Sprint
- Sprint: S23
- Capa: Core + Gateway
- Riesgo: Alto
- Gate: Sí

## SSOT (obligatorio)
- `docs/arquitectura/config.md` - config model and defaults
- `docs/arquitectura/operaciones.md` - server operation
- `src/saar/config_loader.gleam` - parsing/validation

## Inputs (obligatorio)
- Config keys usadas (con defaults esperados):
  - `SAAR_CONFIG_PATH` o ruta por default
- Supuestos:
  - La actualización de config es por reemplazo de fichero (write+rename).
  - Si la configuración nueva no valida, se conserva la previa.

## Outputs (obligatorio)
- Codigo:
  - Nuevo actor `ConfigReloader` (estado de config, debounce, reload flow).
  - Watcher de archivo (poll o notify) para detectar cambios.
  - Evento `ConfigUpdated` para propagar a consumidores.
  - Logs con marcador estable `CONFIG_RELOAD_FAILED` cuando falla.
- Tests (inventario exacto):
  - `test/unit/config_reloader_test.gleam`:
    - `reload_on_valid_config_updates_state`
    - `reload_on_invalid_config_emits_rejected`
    - `reload_debounce_coalesces_changes`
  - `test/unit/config_loader_integration_test.gleam`:
    - `reload_uses_config_loader_and_returns_error_marker`
  - `test/integration/config_reload_test.gleam`:
    - `reload_applies_valid_config_without_restart`
    - `reload_invalid_config_keeps_previous_values`
    - `reload_invalid_config_logs_error`
    - `reload_updates_limits_for_gateway`

## Límites y defaults (obligatorio)
- Debounce sugerido: 250-500ms (exacto en implementación).

## Acceptance Criteria (obligatorio)
- Casos correctos:
  - Config válida se aplica sin reiniciar el proceso.
  - Config válida actualiza límites usados por gateway y task store.
  - Si cambian sources de perfiles, se recargan perfiles.
- Casos incorrectos:
  - Config inválida reemplaza la configuración actual.
  - Config inválida tumba el proceso o corta peticiones activas.

## Semántica de errores (obligatorio)
- Log con marcador estable `CONFIG_RELOAD_FAILED` y detalle del error.

## Evidence reproducible (obligatorio)
- `gleam test` con exit 0.

## No-goals (obligatorio)
- No hot-reload de `api_key` salvo si se declara explícitamente como recargable.
- No watcher de directorios múltiples (solo config principal).

## Dependencias
- Ninguna
